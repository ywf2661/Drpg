# Drpg 1단계: 버티컬 슬라이스 설계

- 날짜: 2026-10-15
- 목표: 디아블로/울티마 계열 2.5D 웹 ARPG의 핵심 조작감(쿼터뷰, 클릭 이동, 근접 전투)을 브라우저에서 플레이 가능한 형태로 검증한다.
- 결정 사항: 3D 렌더링, 싱글 우선(멀티 확장 고려), 클릭 이동, CC0 3D 모델 + 애니메이션, three.js 직접 사용.

## 1. 기술 스택

| 항목 | 선택 |
|---|---|
| 언어/빌드 | TypeScript + Vite |
| 렌더링 | three.js (GLTFLoader, AnimationMixer) |
| 테스트 | Vitest (`npm test`) |
| 에셋 | KayKit Adventurers 1.0, KayKit Skeletons 1.0 (CC0, GLB, 애니메이션 내장) |

의도적으로 쓰지 않는 것: ECS 라이브러리(엔티티 수백 개 전까지 배열로 충분), 물리 엔진(원형 충돌 + 격자로 충분), UI 프레임워크(HTML/CSS 오버레이).

## 2. 구조

### 2.1 sim / render 분리

- `src/sim/`: 게임 규칙. **three.js를 import하지 않는다.** 순수 데이터와 함수만 사용한다.
- `src/render/`: three.js로 sim 상태를 매 프레임 읽어 모델·애니메이션에 반영한다. sim 상태를 수정하지 않는다.
- 입력은 sim을 직접 조작하지 않고 **커맨드**로 변환해 전달한다.
  - `{ type: 'move', x, z }`
  - `{ type: 'attack', targetId }`
- 멀티플레이 확장 시 커맨드를 서버로 보내고, 서버가 같은 sim을 실행한다.

### 2.2 파일 구성

```
index.html
public/models/        Knight.glb, Skeleton_Minion.glb, Skeleton_Warrior.glb
src/
  main.ts             부트스트랩, 게임 루프
  input.ts            마우스 → 레이캐스트 → 커맨드
  sim/
    world.ts          엔티티, 맵 그리드, step(world, commands)
    path.ts           그리드 A*
    world.test.ts     sim 테스트
  render/
    render.ts         카메라, 조명, 바닥/장애물, 모델 로드, 애니메이션 동기화
```

### 2.3 게임 루프

- sim은 60Hz 고정 틱으로 진행한다(누적 시간 방식). 렌더는 requestAnimationFrame.
- 난수는 시드 기반 PRNG를 world가 소유한다. 같은 시드 + 같은 커맨드 시퀀스 = 같은 결과.

## 3. 게임플레이

### 3.1 카메라

- OrthographicCamera, 고정 각도(수평 45°, 내려다보는 각 약 40°). 회전 없음.
- 주인공을 부드럽게 추적(lerp). 마우스 휠로 줌(최소/최대 제한).

### 3.2 맵

- 32×32 그리드, 1칸 = 1m. 각 칸은 통행 가능 또는 장애물.
- 장애물(벽·기둥·상자)은 1단계에서 기본 도형(박스)으로 렌더링한다.
- 맵 레이아웃은 코드 내 문자열 배열로 정의한다.

### 3.3 이동

- 땅 클릭 → 목표 칸 → A* 8방향 경로(장애물 모서리 대각선 통과 금지) → 웨이포인트를 따라 이동(주인공 4m/s).
- 마우스 버튼을 누르고 있는 동안 0.15초마다 커서 위치로 move 커맨드를 재발행한다.
- 장애물 칸이나 도달 불가능한 칸을 클릭하면 무시한다.
- 엔티티 간 원형 충돌(반경 0.4m)로 서로 밀어내 겹침을 방지한다. 장애물 칸 안으로 밀려 들어가지 않는다.

### 3.4 전투

- 근접 사거리는 모든 엔티티 공통 1.5m(중심 간 거리).
- 몬스터 클릭 → 주인공이 접근 → 사거리 안에서 공격을 반복. 대상 사망 또는 새 커맨드 시 중단.
- 공격은 공격 간격 중 **40% 시점에 타격 판정**한다. 그 순간 대상이 사거리 밖이거나 이미 죽었으면 빗나간다.
- 데미지는 [최소, 최대] 범위의 정수, 시드 PRNG로 결정한다.
- 체력이 0 이하가 되면 사망. 죽은 엔티티는 이동·공격·충돌·타게팅 대상에서 제외되고 시체로 남는다.

| | 체력 | 데미지 | 공격 간격 | 이동 속도 | 수량 |
|---|---|---|---|---|---|
| 주인공 (Knight) | 100 | 8–12 | 0.8초 | 4m/s | 1 |
| Skeleton Minion | 30 | 3–5 | 1.2초 | 2.5m/s | 6 |
| Skeleton Warrior | 60 | 6–9 | 1.4초 | 2m/s | 2 |

### 3.5 몬스터 AI

- 상태: `idle` → (주인공이 8m 이내) `chase` → (사거리 이내) `attack` → `dead`.
- chase 중 0.5초마다 주인공 위치로 경로 재계산.
- 주인공이 죽으면 몬스터는 idle로 돌아간다.

### 3.6 애니메이션 매핑

sim 상태 → KayKit 클립. 전환 시 0.15초 크로스페이드.

| 상태 | 클립 |
|---|---|
| idle | `Idle` |
| 이동 | `Running_A`(주인공), `Walking_D_Skeletons`(몬스터) |
| 공격 | `1H_Melee_Attack_Chop` (공격 간격에 맞춰 재생 속도 조절) |
| 피격 | `Hit_A` (연출 전용, sim에 영향 없음) |
| 사망 | `Death_A` (1회 재생 후 마지막 프레임 유지) |

### 3.7 UI (HTML 오버레이)

- 좌하단: 주인공 체력바.
- 상단 중앙: 마우스를 올린 몬스터의 이름과 체력바. 몬스터 위에서는 커서가 공격 커서로 바뀐다.
- 주인공 사망 시 "사망", 몬스터 전멸 시 "클리어" 오버레이. R 키로 같은 시드로 재시작.

## 4. 범위 밖 (1단계)

아이템/인벤토리, 레벨/경험치, 스킬/마나, 던전 생성·다층 구성·던전 타일 모델, 사운드, 저장, 멀티플레이, 모바일 터치, 모델 용량 최적화.

## 5. 완료 기준

1. `npm run dev` 실행 시 브라우저에 Knight가 맵 위에 서 있다.
2. 땅 클릭 시 장애물을 피해 달려가고, 누르고 있으면 커서를 계속 따라간다.
3. 몬스터 클릭 시 다가가서 베고, 상단 체력바가 줄어든다. 쓰러진 몬스터는 시체로 남는다.
4. 몬스터가 주인공을 발견하면 쫓아와 공격하고, 주인공 체력바가 줄어든다.
5. 주인공 사망 시 "사망", 전멸 시 "클리어"가 뜨고, R 키로 재시작된다.
6. `npm test`에서 sim 테스트가 모두 통과한다: 길찾기(우회 경로, 막힌 목적지), 이동, 공격 사거리·데미지 적용, 사망 처리, 같은 시드 재현성.
7. `npm run build`가 오류 없이 끝난다.
