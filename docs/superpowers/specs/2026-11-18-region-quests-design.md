# 지역 의뢰 설계 (지역마다 다른 목표)

- 날짜: 2026-11-18
- 이어서: `2026-11-17-camp-story-design.md`(야영지·이야기 4단계), `2026-11-17-ruins-gimmicks-design.md`(시련의 제단·무덤)
- 상태: 설계. 사용자 요청 "야영지 → 초원 → 3구역 단서 → 5구역 보스 → 야영지가 지역마다 똑같아 단조롭다, 깊이 있게". 접근은 추천안(A)으로 진행(사용자 상시 지시: 추천안 채택).

## 왜

지금 네 지역이 모두 같은 틀이다: 1~5구역 일직선, 3구역에 단서 하나(읽기만), 5구역 보스. 지역마다 할 일이 다르지 않고, 플레이어가 고를 것도 없다.

## 목표 / 아닌 것 / 실패

- 목표
  - 지역마다 **의뢰** 하나. 2·3·4구역에 **의뢰 대상**이 하나씩(셋), 지역마다 **종류가 다르다**.
    | 지역 | 의뢰 | 대상(글자) | 하는 일 |
    |---|---|---|---|
    | 초원 | 실종된 정찰병 | 정찰병의 흔적(`L`) | 찾아서 읽는다(탐색) |
    | 설원 | 꺼진 봉화 | 꺼진 봉화(`J`) | 불을 붙이면 몬스터 물결 2번을 버틴다(방어) |
    | 미궁 | 열쇠지기 | 잠긴 궤(`k`) | 정예 1 + 졸개 2가 지킨다. 다 잡고 연다(사냥) |
    | 폐허 | 봉인 제단 | 봉인 제단(`O`) | 깨면 둘레에 저주받은 무덤 2개가 솟는다(위험) |
  - 의뢰는 **선택**이다. 보스로 바로 가도 된다. 대상을 하나 끝낼 때마다 **그 지역 보스 체력 −10%**, 셋 다 끝내면 **스킬 포인트 +1**과 **보스 전설 확정**.
  - 대상마다 이야기 조각(이름·글)이 나온다. 조각 순서는 **찾은 순서**(구역 순서가 아님). 셋째 조각이 지금의 단서(다음 지역을 가리킴)다.
  - HUD 임무 줄에 진행: `초원 가장 깊은 곳을 살펴본다 · 실종된 정찰병 1/3`.
  - 진행은 저장되고 **죽어도 남는다**(끝낸 구역의 대상은 다시 나오지 않는다). 이야기 단계가 넘어가면 0으로.
- 아닌 것: 곁던전(안 B), 야영지 곁다리 의뢰·대사 선택지(안 C), 새 그림(기존 그림 + 색), 지난 지역 의뢰 다시 하기(지난 지역엔 대상이 없다), 회차별 다른 조각 글.
- 실패
  - 의뢰를 안 해서 진행이 막힌다(→ 선택이라 막히지 않는다).
  - 대상을 못 알아본다(→ 이름표, HUD 줄).
  - 봉화·궤가 너무 세서 피하게 된다 / 너무 약해 할 맛이 없다.

| 안 | 내용 | 판단 |
|---|---|---|
| **A. 지역마다 다른 의뢰(대상 3개, 선택, 보스 약화·보상)** | 위 | **고름**. 단조로움의 원인(같은 틀·고를 것 없음)을 바로 겨냥, 기존 기믹(시련 물결·지킴이 상자·무덤·정예)을 다시 써서 작다 |

## 설계

### 규칙(`src/sim/rules.ts`)

- `Story`의 `clue` → `quest: { kind: QuestKind; name: string; sign: string; marks: { name: string; text: string }[] }`(조각 3개). `QuestKind = 'note' | 'beacon' | 'keeper' | 'seal'`.
- `MARK_FLOORS = [2, 3, 4]`, `QUEST = { weaken: 0.1, beacon: ['mmm', 'mwa'], graves: 2 }`.
- 진행 `marks`: 비트(2구역 = 1, 3구역 = 2, 4구역 = 4). 순수 함수: `markBit(floor)`(대상 구역이 아니면 0), `markCount(marks)`, `bossHpScale(count) = 1 − weaken × count`.
- `CLUE_FLOOR`는 없앤다.

### 맵(`src/sim/wilds.ts`)

- `makeMap(..., clue = false)` → `makeMap(..., mark?: string)`(놓을 글자). `withClue` → `withMark(map, seed, letter)`: 놓는 자리 규칙은 지금 그대로. 궤(`k`)면 둘레 2칸 빈 자리에 `W`(정예 전사) 1, `m` 2.

### sim(`world.ts`·`gimmicks.ts`·`core.ts`)

- 상자 종류: `L` → `'clue'`(그대로), `J` → `'beacon'`, `k` → `'keeper'`(지킴이: `C`처럼 `guards`), `O` → `'seal'`. 셋을 `BLOCKS`에 넣는다.
- 끝내면 sim이 `w.marked = true`(main이 읽고 지운다):
  - 흔적: 누르면(지금 단서처럼 `talk = 'clue'`) + marked.
  - 봉화: 누르면 물결 시작(시련의 제단과 같은 방식, 물결 표는 `QUEST.beacon`), 마지막 물결이 다 쓰러지면 `open` + marked. 전리품 없음.
  - 궤: 지킴이가 다 쓰러진 뒤 열면 평소 지킴이 상자 전리품 + marked.
  - 봉인: 누르면 `open`, 둘레 3m에 무덤 `QUEST.graves`개 + marked.
- `w.sureLegend`: 참이면 보스 전설 확률 1.

### main

- 이 구역 대상: 지금 단계 지역 && `markBit(floor)` && 그 비트가 아직 없음 → 지역의 글자로 맵에 놓는다.
- 보스 구역(지금 단계 지역의 5구역): 보스 체력 × `bossHpScale(count)`, count = 3이면 `sureLegend`.
- `w.marked`를 보면: 비트 켜기 → 조각 글(찾은 순서) + `(실종된 정찰병 2/3 · 개미귀신이 약해졌다)` 대화 → 셋째면 스킬 포인트 +1(지금 구역과 들어온 상태 둘 다) → 저장 → HUD 줄 갱신.
- 이름표: 안 끝난 대상 위에 `quest.sign`.
- 단계가 넘어가면(`afterClear().advanced`) `marks = 0`.

### 저장(`save.ts`)

- `marks`: 정수 0~7, 없으면 0.

### 봇

- 봇은 의뢰를 하지 않는다(대상은 맵에 놓인다 — 궤의 지킴이는 길에 걸리면 싸운다). 밸런스 테스트가 그대로 통과해야 한다.

## 만드는 쪽이 정한 것

- 약화 −10%/개, 봉화 물결 2번(`mmm`, `mwa`), 봉인 무덤 2개 — 수치는 `QUEST`에서 조정.
- 봉화 그림 = 시련의 제단(푸른 빛), 봉인 = 성소(붉은 빛), 궤 = 상자(금빛). 새 그림 없이 색만.
