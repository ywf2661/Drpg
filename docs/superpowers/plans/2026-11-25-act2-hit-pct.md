# 몬스터 피해 % 전환 구현 계획 (2막 파밍·성장 1단계)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 2막과 1막 2회차 이상에서 몬스터 한 방을 "직업 기준 체력의 %"로 바꿔, 두 대 맞으면 위험하지만 한 대에 죽지는 않게 한다.

**Architecture:** 몬스터 피해는 거의 모두 `roll(w, a)`(core.ts)를 거친다. 월드에 `hitScale`(0 = 지금 공식)을 두고, 0이 아니면 `roll`의 몬스터 쪽을 기준 체력 × 종류별 비율로 바꾼다. 예고 공격·보스 큰 기술은 새 도우미 `hitOf(w, e, mult, pct?)`로 비율을 직접 정한다. 난수 소비 횟수는 그대로 둔다(결정성).

**Tech Stack:** TypeScript, vitest(`npm test -- <파일>`), 시뮬은 `src/sim/`.

**Spec:** docs/superpowers/specs/2026-11-25-act2-loot-growth-design.md (1절)

## Global Constraints

- 적용: 2막 땅 전부(깊이 26 이상) + 1막 2회차 이상(`cycle ≥ 1`). 1막 첫 판(`cycle = 0`, 깊이 25 이하)은 지금 공식 그대로.
- 기준 체력 = `heroMaxHp(MAX_LEVEL, cls) + CLASSES[cls].helms[3].hp` (기사 620 · 궁수 507 · 강령술사 448 · 마법사 394).
- 한 방 = 기준 체력 × 비율 ÷ (1 − `CLASSES[cls].armors[3].reduce`) × hitScale × 정예 1.3 × 통솔 1.3, 그 뒤 평소 갑옷 감소.
- 비율: 졸개 0.10, 궁수·마법사 0.15, 전사 0.25, 해골 왕·보스 0.30, 예고 공격·함정 0.40, 보스 큰 기술 0.55.
- hitScale: 2막은 깊이 26에서 ×1.0 → 깊이 50에서 ×1.2(직선, 넘으면 1.2), 1막 2회차 이상은 ×1.0. 회차: `cycle ≥ 2`부터 회차마다 +5%, 최대 +20%.
- 몬스터 체력·속도 공식은 그대로.
- 빠른 개발 순서: 조각마다 그 테스트만, 전체 `npm test`는 커밋 직전 한 번.
- 주석·글은 번역투 없이.

## Review Focus

1. 1막 첫 판의 피해가 한 글자도 안 바뀌어야 한다 → Task 2 테스트 `hitScale 0이면 예전 공식`, 커밋 전 `playthrough.test.ts` 통과.
2. 난수 소비가 같아야 한다(같은 시드 같은 판) → Task 2에서 몬스터 굴림은 예전처럼 `rand` 한 번만.
3. 직업마다 기준 체력·갑옷이 다르다(마법사 4단계 로브 0.2) → Task 2 테스트에 마법사 한 줄.
4. 거점(야영지·천막, 깊이 0)은 1회차 이상이어도 hitScale 1(몬스터가 거의 없음) → Task 1 테스트.
5. 체력 옵션을 올려도 받는 피해가 같아야 한다(실제 최대 체력이 아니라 기준 체력) → Task 2 테스트.

### Task 2: roll()의 % 갈래, 함정, main 연결

**Files:**
- Modify: `src/sim/rules.ts` (World 타입에 `hitScale: number`)
- Modify: `src/sim/world.ts:130` (createWorld 반환값에 `hitScale: 0`)
- Modify: `src/sim/core.ts:467-475` (`roll`), 그리고 새 `hitOf`
- Modify: `src/sim/gimmicks.ts:15` (`trapDmg`)
- Modify: `src/main.ts:120` 근처(createWorld 바로 뒤 `w.hitScale = hitScale(depth, cycle)`)
- Test: `src/sim/hits.test.ts`

**Interfaces:**
- Consumes: Task 1의 `HIT`, `hitBase`, `hitScale`
- Produces: `core.ts`: `export function hitOf(w: World, e: Entity, mult: number, pct?: number): number` — hitScale이 0이거나 pct가 없으면 `Math.round(roll(w, e) * mult)`, 아니면 `Math.round(roll(w, e) * pct / HIT[e.kind])`(roll에 든 종류 비율을 pct로 바꿔 끼움)

- [ ] **Step 1: 실패하는 테스트** (`hits.test.ts`에 추가)

```ts
import { createWorld, step } from './world';
import { roll, hurt, hitOf } from './core';
import { HIT } from './rules';

const knight4 = (map = ['Hw']) => { const w = createWorld(1, map); w.gear.armor = 4; w.gear.helm = 4; w.hitScale = 1; return w; };

test('전사 평타: 4단계 갑옷 기사에게 기준 체력의 약 25%(굴림 폭 0.8~1.2)', () => {
  const w = knight4(); const hero = w.entities[0]; const e = w.entities[1];
  for (let i = 0; i < 50; i++) {
    hero.hp = hero.maxHp = 9999;
    const got = hurt(w, hero, roll(w, e), e);
    expect(got).toBeGreaterThanOrEqual(Math.floor(620 * 0.25 * 0.8));
    expect(got).toBeLessThanOrEqual(Math.ceil(620 * 0.25 * 1.2));
  }
});

test('체력 옵션을 올려도 받는 피해는 같다', () => {
  const a = knight4(), b = knight4();
  b.mods.armor = [{ kind: 'life', value: 30 }];
  expect(roll(b, b.entities[1])).toBe(roll(a, a.entities[1]));
});

test('정예는 ×1.3, 마법사는 자기 기준 체력', () => {
  const a = knight4(), b = knight4();
  b.entities[1].elite = true;
  expect(roll(b, b.entities[1]) / roll(a, a.entities[1])).toBeCloseTo(1.3, 1);
  const z = knight4(); z.cls = 'wizard';
  const r = roll(z, z.entities[1]);
  expect(r).toBeGreaterThanOrEqual(Math.floor(394 / 0.8 * 0.25 * 0.8));
  expect(r).toBeLessThanOrEqual(Math.ceil(394 / 0.8 * 0.25 * 1.2));
});

test('hitScale 0이면 예전 공식, 난수도 한 번만', () => {
  const a = createWorld(1, ['Hw']), b = createWorld(1, ['Hw']);
  b.hitScale = 1;
  roll(a, a.entities[1]); roll(b, b.entities[1]);
  expect(b.rng).toBe(a.rng);
});

test('hitOf: pct를 주면 그 비율, 안 주면 배율', () => {
  const w = knight4();
  const tell = hitOf(w, w.entities[1], 2, HIT.tell);
  expect(tell).toBeGreaterThanOrEqual(Math.floor(620 / 0.7 * 0.4 * 0.8));
  expect(tell).toBeLessThanOrEqual(Math.ceil(620 / 0.7 * 0.4 * 1.2));
  const a = createWorld(1, ['Hw']), b = createWorld(1, ['Hw']); // hitScale 0: 예전처럼 굴림 × 배율
  expect(hitOf(a, a.entities[1], 2, HIT.tell)).toBe(Math.round(roll(b, b.entities[1]) * 2));
});
```

- [ ] **Step 2: 실패 확인** — `npm test -- src/sim/hits.test.ts` → FAIL
- [ ] **Step 3: 구현**
  - `roll`의 몬스터 쪽: `w.hitScale > 0`이면 `scale = hitBase(w.cls) * HIT[a.kind] * w.hitScale / ((lo + hi) / 2) * (a.elite ? ELITE.dmg : 1) * (led(w, a) ? ELITE_FX.auraDmg : 1)`. 굴림(`lo + floor(rand × (hi − lo + 1))`)은 그대로 한 번.
  - `hitOf`는 Interfaces 그대로.
  - `trapDmg(w, base)`: `w.hitScale > 0`이면 `Math.round(hitBase(w.cls) * HIT.tell * w.hitScale)`, 아니면 예전.
  - `main.ts`: createWorld 바로 뒤 `w.hitScale = hitScale(depth, cycle)`. 봇(bot.ts)은 건드리지 않는다(0 그대로라 1막 첫 판 밸런스 테스트가 지켜짐).
- [ ] **Step 4: 통과 확인** — 같은 명령 → PASS
